# Enterprise Retail Data Engineering Pipeline Using Azure Databricks, Python, PySpark, SQL, and Delta Lake

Built by Avinash B — Senior Data Engineer, Richmond, VA · [LinkedIn](https://www.linkedin.com/in/avinash-b-databricks-architect)

I built this to have one public project that shows how I actually structure
a data pipeline, end to end: ingest messy source files, clean them in a
separate layer, model a few Gold tables properly, and write down the
trade-offs instead of hiding them.

It uses synthetic retail data generated by code in this repo. No employer
data, no downloaded dataset.

![Python](https://img.shields.io/badge/Python-3.11+-blue) ![Spark](https://img.shields.io/badge/Apache_Spark-3.5-orange) ![Delta](https://img.shields.io/badge/Delta_Lake-3.2-green)

## What it does

CSV, JSON lines, and Parquet land in **Bronze** unchanged. **Silver**
cleans: duplicates removed, dates parsed from two formats, types cast,
bad rows (negative amounts, missing keys) sent to quarantine with the
rule they failed. **Gold** is a small set of tables built for questions -
sales by category and month, top products, inventory below reorder level,
customer spend bands - plus SCD Type 2 dimensions for customers and
products.

Orders load incrementally: a Delta MERGE on `order_id`, with only rows
past the stored `updated_at` watermark read in.

```
sources ──> Bronze (Delta) ──> Silver (Delta) ──> Gold (Delta) ──> SQL / BI
                    │               │
                    └── quarantine (failed quality rules)
```

Diagram sources: `docs/diagrams/medallion_architecture.mmd` and
`docs/diagrams/pipeline_flowchart.mmd` (open the `.html` versions to view).

## Run it locally

Needs JDK 17 for the Spark steps. The generator and tests don't need Spark.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/data_generation/generate_retail_data.py   # writes data/sample/
pytest tests/ -q
python src/ingestion/bronze_ingestion.py
python src/transformations/silver_transformations.py
python src/transformations/gold_transformations.py
```

Or: `make data && make test`

## Run it on Databricks

1. Import this repo (Repos / Git folders) or upload the `notebooks/` files.
2. In `config/pipeline_config.yaml`, point `data_root` and the warehouse
   paths at your DBFS or Unity Catalog volume.
3. Run notebooks `01` to `04` in order. They call the same `src/` modules
   the local run uses.

Works on Databricks Community Edition and Azure Databricks. I have not
changed any code path for Databricks - `get_spark()` in
`src/utils/spark_session.py` reuses the injected session there.

## Layout

```
src/data_generation/   seeded synthetic data, dirt included on purpose
src/ingestion/         Bronze
src/transformations/   Silver, Gold, incremental MERGE, SCD Type 2
src/data_quality/      rules (plain Python) + Spark application, quarantine
src/utils/             config, Spark session, logging
sql/                   SQL versions of the main transforms + reporting queries
notebooks/             Databricks-format .py notebooks, 01-04
tests/                 pytest - no Spark needed for most of it
docs/                  architecture, data model, decisions, my working notes, execution report
data/sample/           generated sample files (regenerate any time)
config/                pipeline_config.yaml - paths, tables, watermark
```

## Decisions and limits

`docs/decisions.md` is the honest version: why SCD2 only covers customers
and products, why Gold aggregates overwrite instead of merging, why
Z-ORDER is off by default, and what this project doesn't do (no alerting,
two date formats only, segment bands picked from this dataset).
